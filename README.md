# bee2-tls-gateway

> Last reviewed: 2026-08-13

Шлюз внутрь HTTP, наружу BTLS | OpenSSL/nginx/bee2/ГосСУОК

Контейнер принимает обычный HTTP из приватной сети и поднимает наружу TLS по СТБ 34.101.65 —
на **открытой** реализации [bee2 + bee2evp](https://github.com/bcrypto/bee2evp) (Apache-2.0),
без проприетарного СКЗИ и без ключа ГосСУОК (аутентификация сервера односторонняя).

```
приложение ──HTTP──▶ bee2-tls-gateway ──TLS 0xFF1x──▶ хост, говорящий по-белорусски
  (любой стек)        :1080  (nginx)      DHE-BIGN…
```

## Зачем он нужен

Хост, отвечающий белорусским шифронабором, недостижим для стокового TLS-стека: соединение
обрывается на `ServerHello` с `unknown cipher returned`. Для Node это неисправимо изнутри —
BTLS живёт в libssl, а Node несёт свой OpenSSL. Отдельный процесс с пропатченным OpenSSL —
единственный способ, не переписывая приложение.

## Почему nginx, а не stunnel/socat

| | TCP-туннель | nginx |
|---|---|---|
| Заголовок `Host` | не переписывает — сервер увидит `Host: gateway:1080` | `proxy_set_header Host` |
| Переиспользование соединения | по соединению | `keepalive` (замерено: 1 TLS-соединение на 10 запросов против 10 без него) |
| Проверка собеседника | проверка цепочки без проверки имени принимает **любой** сертификат того же УЦ | `proxy_ssl_verify on` — цепочка и имя одной директивой |
| Ограничение путей | нет | allowlist `location` |

## Проверено вживую

12.08.2026 против боевого банковского хоста `apibel.priorbank.by:9345`, запрос к
токен-эндпоинту с заведомо неверными кредами:

```
{"error_description":"A valid OAuth client could not be found for client_id: probe","error":"invalid_client"}
HTTP 401
2026-08-12T14:45:23+00:00 route=token method=POST status=401 upstream=401 bytes=120 rt=0.087 urt=0.088
```

**`upstream=401` — это и есть доказательство:** 401 пришёл от банка, а не выдуман nginx. Значит
последовательно отработали рукопожатие по СТБ 34.101.65, проверка цепочки по корням ГосСУОК,
сверка имени хоста и подстановка `Host`. Полный цикл 87 мс.

Контроль на том же хосте минутами раньше: `openssl s_client -connect apibel.priorbank.by:9345`
→ `CONNECTED`, 90 байт `ServerHello`, затем `unknown cipher returned`, `Cipher: 0000`. Разница
именно в шлюзе, а не в сети.

## Быстрый старт

```bash
docker build -t bee2-tls-gateway .
docker run --rm -p 127.0.0.1:1080:1080 \
  -e GW_UPSTREAM_HOST=apibel.priorbank.by -e GW_UPSTREAM_PORT=9345 \
  -v "$PWD/ca:/etc/crypto-gw/ca:ro" \
  bee2-tls-gateway
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:1080/healthz   # 200
```

## Переменные

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `GW_UPSTREAM_HOST` | — (**обязательна**) | хост назначения |
| `GW_UPSTREAM_PORT` | `9345` | порт назначения |
| `GW_LISTEN` | `1080` | порт шлюза внутри сети |
| `GW_CA_BUNDLE` | `/etc/crypto-gw/ca/gossuok-bundle.pem` | корни, которыми проверяется собеседник |
| `GW_KEEPALIVE` | `4` | сколько апстрим-соединений держать живыми |

Полный список — в `Dockerfile` и `entrypoint.sh`; там же дефолты и обязательность.

## Граница безопасности

Шлюз **никого не аутентифицирует** — он рассчитан на изолированную сеть, куда нет доступа
извне. Единственная граница, которую он держит сам, — список путей:

- `= /healthz`
- `= /open-banking-authorize/v1.0/oauth2/token`
- `/open-banking/v1.0/`
- всё остальное → 404

Матчинг идёт по уже нормализованному nginx `$uri`, и **тот же** `$uri` уходит в `proxy_pass` —
разрыва «проверили одно, отправили другое» нет.

⚠ Пути пока зашиты в шаблон, хотя описывают API конкретного банка —
[#7](https://github.com/bx-shef/bee2-tls-gateway/issues/7).

Ещё два свойства, которые легко потерять при правках:

- В образе **намеренно нет** `ca-certificates`: доверенный набор — только смонтированная связка
  ГосСУОК. Поэтому подмена хоста назначения на сервер с честным публичным сертификатом не
  пройдёт проверку.
- **Формат лога не содержит пути.** В пути ездит номер счёта, и растекаться в агрегацию логов
  ему незачем.

## Что чем проверяется

| Инвариант | Чем держится |
|---|---|
| Криптостек компилируется, движок грузится, шифронаборы на месте, nginx слинкован с нужным OpenSSL | три гейта внутри `Dockerfile` |
| Корни загружаются и действительно проверяют эталонный сертификат | два гейта в `entrypoint.sh` при старте |
| Плейсхолдеры шаблона синхронны со списком `envsubst`; лог без пути; проверка апстрима включена; forward secrecy раньше переноса ключа; проксируются только известные префиксы | `scripts/check-config.sh` (job `ci`) |
| **Сами эти проверки живы** — каждая краснеет на своей поломке | `scripts/check-config-mutations.sh` (job `ci`) |
| Контейнер стартует, отвечает, отвергает чужие пути и методы, работает непривилегированным | смоук-запуск (job `image`) |

Разделение намеренное: `check-config.sh` проверяет **намерение** (что написано в конфиге),
смоук — **поведение** (что отвечает живой контейнер). Первое ловит опечатку в PR, второе —
всё, что живёт между сборкой и первым запросом.

Третья строка нужна потому, что проверка, которая никогда не краснеет, в CI неотличима от
работающей: обе печатают «ok». `check-config-mutations.sh` вносит порчу нарочно и требует,
чтобы `check-config.sh` покраснел — причём именно той проверкой, которая за эту порчу
отвечает. Одну мёртвую проверку так уже нашли: список путей и лог она стерегла честно, а
переменные nginx — только на вид.

## Известное ограничение

Образ **постоянно потребляет одно ядро**: `bee2evp_init()` поднимает busy-loop как источник
энтропии, и остановить его можно только выходом процесса. Нагрузка сидит в мастер-процессе
nginx, рабочий процесс простаивает. Смягчено `nice -n 19` и лимитом CPU.

⚠ **Не разворачивать на burstable-инстансах** — постоянные 100% одного ядра исчерпают бюджет
CPU-кредитов, после чего затормозится всё на машине. Подробности и почему не патчим bee2 сами —
[#8](https://github.com/bx-shef/bee2-tls-gateway/issues/8).
